# 飞书多维表格交付

本地 Excel 仍是默认可复查交付物。只有用户明确要求写入飞书多维表格时，才走这条路径。先读 `lark-base` skill，用 `lark-cli base +...`，不要把 App Secret 写进说明或仓库。

## 写入前

1. 用用户给的飞书 URL 解析 `base_token`、`table_id`、`view_id`；不要猜表。
2. 先 `+field-list` / `+record-list` / `+view-get-visible-fields`，按现表字段写，不擅自改表结构。
3. 用户要求加列时再 `+field-create`。`+field-create` 不能插列位置，列序靠 `+view-set-visible-fields`；可见字段列表必须包含所有仍要显示的列。
4. 同 Base 若已有相关岗位表，先按姓名对齐已有约面/进展，再写新表。不要给重叠人选重新发明约面状态。

## 本用户交付习惯

- 常见交付是飞书表，不只 Excel。
- 不要自动填写「约面试」或把 `是否约面` 改成约面。默认保持表里已有值；新记录默认「待确认」，除非用户明确给了结论，或相关旧表已有可对齐状态。
- `手机号`、`邮箱` 必须独立成列，不要只写在备注里。有联系方式后，从备注去掉「联系：」行。
- 列序：`面试情况` → `手机号` → `邮箱` → `备注`。
- 备注只留来源、分层、文件名、地点风险和用户补的判断；不要重复电话邮箱。
- 姓名优先用原始下载文件名/渠道名，不用简历正文里的英文名或别名覆盖。
- 简历附件走 `+record-upload-attachment`，不要把本地路径伪造成附件单元格。
- 身份用 `--as user`。`--json @` 必须用当前工作区相对路径。

## 联系方式

从本地脱敏映射、旧备注或简历正文回填电话和邮箱。PDF 抽不出来就留空，不要编造。写入后抽查几条，确认独立列有值、备注不再重复同一行联系方式。

## 不要写进飞书的内容

- 未确认 JD 下的全量 AI 等级，当作最终结论。
- 用户没点名的淘汰名单或隐私字段。
- 完整 API key、邮箱授权码、飞书 App Secret。
